# Current-account admission for the staged token marketplace

**Source preparation only.** The live tokenMarketplace service remains404, and its exact Rules candidate remains unactivated. This does not certify restored balances/purchases, complete reward-writer compatibility or whole-app readiness.

The prepared gateway previously relied on decoded callable Auth plus canonical profile ownership. It now captures a server-owned context from current Auth account metadata. Firebase's documented [account lookup](https://docs.cloud.google.com/identity-platform/docs/reference/rest/v1/projects.accounts/lookup) supplies [millisecond createdAt and second-based validSince](https://docs.cloud.google.com/identity-platform/docs/reference/rest/v1/UserInfo). Admin UserMetadata.creationTime formats UTC text at whole-second precision, so it cannot distinguish two same-second account creations. The new lookup preserves the precise value and rejects disabled/deleted accounts, malformed responses, foreign projects/tenants, stale credentials and future/invalid authentication times. Provider failures expose a generic retry error, with an eight-second whole credential/fetch/body budget and no identity cache. ADC uses the documented [Credential.getAccessToken](https://firebase.google.com/docs/reference/admin/node/firebase-admin.app.credential#getaccesstoken).

Only explicitly registered server contexts can accompany an actor. Every gateway-resolved state/purchase/activation/equip/credit transaction checks the same account again before the transaction callback returns, including replay paths. A failed account check aborts queued writes. No new browser input can grant authority. The default Auth lookup is fixed to vybe-daaab; emulator requests require an explicit demo-vybe project and loopback host, and never request production credentials.

Eight new routing assertions failed against the old gateway (five missing current-account rejections and three missing context-forwarding checks). The added unit cases cover exact metadata precision, deleted/malformed/unavailable accounts, credential/body timeouts, loopback restrictions, claim/cutoff validation, forged or borrowed contexts, same-second replacement and transaction rejection before commit/return. Actual Node22.23.5 HTTP callable/demo Auth/Firestore verification passes eight cases: guest rejection; real demo JWT, state and once-only daily credit; disabled/deleted account rejection; disabled/replaced account before credit commit; failed commit; and an imported same-second recreation that leaves Admin UTC metadata equal while the precise context correctly rejects it. No real account/provider action occurred. The exclusive demo project was independently checked to contain zero accounts/documents, then owned helpers were stopped.

Remaining release requirements are explicit: durable account-incarnation ownership for all UID-only ledgers and receipts, legitimate-history reconciliation, matched challenge/badge/XP writers, deployed composite indexes and the exact coordinated Rules/backend/client cutover. A fresh request still needs that durable ownership policy to prevent an earlier UID's records being adopted. Firebase auth_time/iat have second precision; this work does not claim to distinguish every old token issued within the same second as an operator's UID recreation. Unbound internal actor compatibility is staged and is not a public admission bypass. No production Function, Rules, Auth/provider configuration, account, wallet or client publication changed in this phase.
