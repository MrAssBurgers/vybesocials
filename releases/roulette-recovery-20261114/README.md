# Existing Roulette recovery — prepared, not released

The active `/roulette` page called an absent `findRouletteMatch` endpoint (production preflight404). Its raw queue/match collections have no live access block. The old hook could restore cancelled or retired matches, overlapped polls and ignored failed leave writes. Audio/video choices only navigated to a profile.

The candidate adds the missing Firebase callable and keeps all matching authority in private, server-owned records. Current Auth creation/revocation and protected canonical profile/binding are checked, including before commit. Queues are separated by mode. A captured operation has a stable receipt; cancellation before a delayed join leaves a tombstone, so retry cannot revive it. Reload can attach to one existing owned search, expired presence is excluded, blocks and existing parental feature restrictions are honored, and old cleanup cannot delete a newer queue. No historical legacy Roulette rows are adopted or deleted. New private paths inherit the existing browser denial; no new Rules activation is required.

Matched text/audio/video handoff creates one participant conversation with correctly scoped memberships. Audio/video reserve one call initiator and use the existing CallStore flow after an explicit user action. Actual provider connectivity, camera/microphone behavior, incoming-call delivery and physical devices remain separate checks. Existing report/block controls are wired to the verified partner. The page has native pressed interest choices, a five-interest limit, acknowledged leave/retry, a usable ended view and reduced-motion search decoration.
