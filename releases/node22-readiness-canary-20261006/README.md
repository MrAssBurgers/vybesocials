# Existing social services compatibility canary

Eight named Firebase functions are now ACTIVE on Node 22: `readSocialPostList`, `readSocialPostPreviews`, `readPostComments`, `readPostCommentCounts`, `managePost`, `manageSpaces`, `communityManage`, and `sendDmMessage`. Their actual deployed archive hashes match the checked candidates. Every original file except `package.json` and `package-lock.json` is byte-identical. The manifests update the Node engine and proxy-addr, plus grpc-js where its older version was present; other dependency entries are retained.

Before deployment, all 40 distinct bundles for the 230 remaining Node 20 services loaded their real compiled entry modules under Node 22.23.3 with outgoing networking disabled, resolved all 230 entrypoints, and passed their type projects. Two exact dependency sets were installed with scripts disabled and all 300 installed package versions per set checked. These checks do not prove native media processing, signed-in behavior, event delivery, or every feature. The previous core release passed the full 4,844-test suite and production build; those root checks were not repeated for this manifest-only archive checkpoint.

Verification found an unexpected 20-instance default in six services, despite source/runtime-only API updates. Their previous Cloud Run revisions had unset maxima, with an effective default of 100. Six separate field-scoped corrections completed and now explicitly retain 100. All other effective service configuration, triggers and build environment match. This is a representation change, not a raw configuration hash match. The two services with previously explicit limits retained them. Future rollouts must preserve validated effective limits in the update and verify the result.

All eight live empty unauthenticated requests return 401/UNAUTHENTICATED. No account or content writes were used for those probes. The complete post-release inventory has 233 ACTIVE services: 11 Node 22 and 222 Node 20. Other 225 metadata rows are unchanged after normalizing object keys and unordered event-filter sets. See [verification.json](verification.json) for source hashes, configurations, checks and limits.

The existing user-readiness goal remains active. Remaining runtime migrations, other security checks, legitimate historical-content restoration, and physical Play Store package adoption, loading, location and Clips performance are still open. This release changes backend compatibility and dependencies; it does not establish instant phone loading or full readiness. No frontend publication or native binary distribution occurred in this checkpoint.
