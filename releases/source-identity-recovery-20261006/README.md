# Hosted client source identification

The hosted archive's version writer reports commit unknown because Git metadata is absent. A commit label must not be invented or copied from a stale public manifest. The version writer now adds source_schema, source_sha256 and source_files independently of Git, while retaining its honest commit and existing entry hash fields. This identifies the checked client input tree in archive builds; it does not repair the separate older browser response by itself.

Schema vybe-client-source-v1 hashes sorted, length-delimited paths and contents in src, public and scripts plus root package/lock/build/type/style configuration and index.html. Recognized text inputs normalize CRLF to LF so a Windows checkout and source archive compare identically. Binary assets retain exact bytes. Public native-link metadata and extensionless hosting headers are included. Environment, hidden local, .local and generated version/Despia/boot-theme files are excluded; generated output is represented by the existing entry SHA. Symlink inputs are rejected. No secret values or environment files are published.

The fingerprint proves matching client source inputs only. It does not attest the installed compiler/dependencies, deployment environment values, Firebase backend revision, native permissions or production data. Those retain their separate validation gates. Git-backed and non-Git builds keep their original commit behavior; an archive nested inside another repository cannot accidentally inherit its parent's commit label.
