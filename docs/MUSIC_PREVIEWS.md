# Music previews and catalog approval

`readMusicCatalog` restores the existing Music Gallery without opening direct client reads of `licensed_tracks`, `track_usage`, or provider credentials. The callable requires the authenticated UID and a strictly verified canonical profile, validates its small input, limits requests to 60/minute/account, and scans 25 catalog documents per page in document-ID order. Empty filtered pages can still have a next cursor. There is no popularity or recommendation claim.

An authorized operator must deliberately approve each catalog document. Required fields are `is_active: true`, `preview_approved: true`, `license_status: 'approved'`, and a nonempty `license_reference` (maximum 500 characters). Optional `license_expires_at` is an ISO date string in the future. The server does not verify copyright ownership or infer rights from a provider or a historical track row. Existing records are not approved automatically. There is no new browser approval UI, provider integration, credential storage, or production migration in this change.

Metadata must include `title`, `artist`, `genre`, positive finite `duration` in seconds, and `preview_url`. Optional `preview_seconds` is at most 30, defaults to 30, and is capped at the track duration. Only the resulting preview metadata and an optional valid HTTPS artwork URL are returned; full audio URLs, licensing references, provider credentials, and arbitrary document fields are omitted.

Remote preview URLs require HTTPS, a public-style DNS hostname, no embedded credentials, and no IP literals, local/internal suffixes, or single-label hosts. The backend never fetches remote media. URL checks cannot guarantee DNS behavior, provider availability, or a recording's rights; operator review remains required. The seven existing named `/sounds/*.wav` app assets are accepted only with `asset_kind: 'app_sound_effect'`, and the UI labels them as app sound effects. They are not presented as songs or recordings by invented artists. No new recordings are bundled.

Previews start only after an explicit Play press, confirm playback only after the browser accepts it, expose retryable failures, and stop on account-epoch changes, view teardown, hidden pages, and pagehide. Volume and mute change the actual media element. The gallery limits preview playback to 30 seconds or the shorter approved duration. Already fetched bytes and copied public/provider URLs cannot be revoked by the UI; approval is checked at catalog load, not on every audio byte request. Only one shared music player is active at a time.

The gallery intentionally states that attaching music to video exports is not implemented. Sharing creates a normal post with the name and optional artwork, without audio. The missing usage-counter callable is no longer invoked by the gallery; no fabricated play counts, popularity, XP, or music attachment success is shown. `uploadSound` is still a provider stub with no binary transport. Its domain-error or metadata-only reply cannot confirm an audio upload, and the chosen file remains available to the existing dialog.

Deploy the callable and client together before expecting the catalog to load. Without the callable, the UI shows an error and Retry; with no deliberately approved records, it shows an empty catalog. Operator approval and actual licensed media provisioning remain separate deployment tasks.

Verification uses synthetic metadata and mocked media elements, plus `scripts/test-music-catalog-backend.mjs` against an isolated `demo-*` Firestore emulator. No copyrighted recording is fetched, no production catalog is seeded, and no real provider account is invoked. Live playback QA should use a locally generated synthetic WAV or an accurately labeled existing app effect only.
