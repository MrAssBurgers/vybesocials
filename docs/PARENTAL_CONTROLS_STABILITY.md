## Trusted historical parental recovery candidate

Historical controls now have a concrete operator review path through `scripts/review-parental-recovery.mjs` and the private Admin SDK helper `parentalRecoveryAuthority`. Neither is a public callable or client approval endpoint. The existing panel explains the review-required error, keeps the old settings/PIN intact, links the existing Contact page and offers refresh after review. A network failure still presents the ordinary retry state.

Preparation is read-only. It verifies current non-disabled Auth incarnation, canonical profile and protected active binding, checks the unique historical record and emits a private review-required plan. It records exact Firestore creation/update versions (including nanoseconds), a whole-record fingerprint, current binding revision and a fresh review UUID. It contains no PIN hash/salt or source field contents. Preparation does not establish independently reviewed historical ownership. A trusted operator must verify that ownership separately and record the review case; an email match or client assertion is insufficient.

Run from the repository root using existing authorized Admin SDK credentials, after compiling Functions. Keep plans inside the ignored work directory; the tool refuses overwrite and resolves real paths to prevent escaping that directory. These examples are placeholders, not instructions to approve a particular account:

```sh
node scripts/review-parental-recovery.mjs --action=prepare --project=vybe-daaab --uid=CURRENT_UID --profile-id=CANONICAL_PROFILE_ID --source-id=HISTORICAL_CONTROL_ID --review-case=INDEPENDENT_REVIEW_CASE --output=work/parental-review.json
node scripts/review-parental-recovery.mjs --action=apply --project=vybe-daaab --plan=work/parental-review.json --reviewer-uid=CURRENT_AUTHORIZED_REVIEWER_UID --confirmed-case=INDEPENDENT_REVIEW_CASE
```

Application requires trusted Admin SDK access plus a current non-disabled reviewer Auth user with an existing admin claim. The reviewer UID is an eligibility/audit check, not authentication for a public request. The tool does not provision credentials or grant claims. It requires an exact confirmed case and rechecks reviewer/owner incarnations, source versions/fingerprint, canonical binding and unique control authority. Retired previous owners require a matching protected transferred binding; every previous owner ID other than the target UID, including a profile-ID alias, must have no active Auth account. Duplicate records, foreign target collisions, changed source/authority or recreated accounts fail without modification.

One transaction archives every original field and source version in `_parental_controls_archive`, binds the original control to the current UID and records a durable `_parental_recovery_receipts` acknowledgement. When the historical source ID differs, the transaction removes that active source only after saving its complete private archive. The original PIN/salt/algorithm, settings, history, counters and active lockout remain unchanged. Existing safe read and normal PIN unlock resume. An exact lost-response retry validates the archive/current binding/result and returns acknowledgement without writes or resetting counters. Normal PIN bookkeeping does not invalidate acknowledgement, while later settings/PIN/revision changes do. Archive/receipt namespaces require no TTL or indexes and remain raw-client denied, including admin-claim clients, under the tested default-deny baseline/candidate Rules.

Auth and Firestore are separate services: fresh Auth checks reduce races but cannot make them one atomic transaction. Independent ownership review remains an operator prerequisite. This workflow does not prove durable confirmed-session admission, HTTP/JWT checks, downstream parental restrictions or physical-device behavior.
